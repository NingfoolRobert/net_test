# IP 重组模块设计原则

以下原则根据 IP 重组模块的设计讨论整理，用于指导后续设计和实现。

1. **先明确方案，再开始实现。** 需要先给出设计方案；确认方案后再进行代码改造，将方案讨论与编码实现分开。
2. **拆分不同层次的职责。** 单个 IP 数据报的分片拼装，与多个未完成数据报的缓存管理分开处理。
3. **按协议层定义数据边界。** IP 重组处理 IPv4 头之后的负载。UDP 头属于该负载，应保留到 UDP 层解析；是否将 UDP 头传给应用层，由 UDP 接收代码决定。
4. **接口表达协议语义。** 避免按位置传入多个容易混淆的参数；将相关分片信息组织成描述对象，并用明确的返回状态表达处理结果。
5. **偏移换算和报文长度遵循 IPv4 规则。** IPv4 分片偏移以 8 字节为单位。接口可使用字节偏移，但字段可表示的最大偏移不代表该偏移对实际报文有效；有效范围还受 IPv4 头长和最大总长度约束。
6. **收齐判断兼顾效率与正确性。** 使用已收字节数减少完整性判断中的全负载扫描，同时保留位图用于判断字节覆盖情况。

设计需准确表达 Identification 在分片识别中的作用、IP 重组与 TCP 重组的层次差异，以及 UDP 包在重组前后的数据结构和流向。
